# Frontend conventions

SvelteKit 5 (runes) + Tailwind v4, talking to the FastAPI backend in `../backend`.

## Where code goes

- `src/lib/api/` — `schema.ts` (generated), `wrapper.ts`, and one adapter per backend router in `*/adapters/`.
- `src/lib/components/` — styled UI with no API calls and no business logic.
- `src/lib/features/<feature>/components/` — feature components.
- `src/routes/` — pages: load data, render feature components, pass them callbacks.

Move something into `components/` once it has been copied three times.

## API types come from the backend

- `src/lib/api/schema.ts` is generated by `npm run gen:api` with the backend running on port 8000. Regenerate after any Pydantic model or route change, run `npm run check`, and fix every call site it reports. Commit `schema.ts`.
- Import request/response types from `$lib/api/schema`. Filter types are derived in the adapter from `operations[...]['parameters']['query']` (see `adapters/children.ts`).
- Value lists for dropdowns come from the generated `*Values` arrays (e.g. `australianStateValues`). Types the backend doesn't send live in `features/<feature>/types.ts`.
- Adapter methods call `apiWrapper<T>(url, { method, body, fetcher })`. It toasts `msg` on every non-GET and turns a 422 into `fieldErrors` keyed by field name.

## Validation lives on the server

Pydantic is the validator. Forms use HTML attributes (`required`, `type`, `minlength`, `maxlength`) plus only the cross-field checks the server can't see, such as confirm-password.

## Dates are strings

Dates stay as ISO strings end to end: `YYYY-MM-DD` for dates, ISO datetimes for timestamps. Compare them as strings and format only for display (`DataCard` `format: 'date' | 'datetime'`, `utils/helpers.ts`). Converting to `Date` objects caused off-by-one-day bugs in UTC+10.

## Pages own data, components own UI state

- Reads: `+page.ts` / `+layout.ts` `load` functions, passing SvelteKit's `fetch` into the adapter and tagging with `depends('app:...')`.
- Writes: the page calls the API and passes a callback down. Components receive data and callbacks as props. The one exception is a self-contained widget reused across pages with no page-specific behaviour.

### Forms

One component per form, taking `onsubmit: SubmitHandler<T>` (`$lib/types/forms`). The page calls the API, handles success (redirect, refresh) and returns the response. The form owns `body`, `errors` and `isLoading`, sets `errors = response.fieldErrors`, and resets `body` when `response.ok`. Reference pair: `features/auth/components/LoginForm.svelte` + `routes/[location_code]/(public)/login/+page.svelte`.

Each input is `<Field label error>` wrapping a native element that takes the snippet's `id`. `routes/layout.css` already styles native inputs, selects and textareas.

### Tabs

`TabbedPanels` takes `tabs: { id, label }[]` and a `panel(id)` snippet, so panel props are type-checked. Tab ids live in `navigation/tabs.ts`.

## Styling

Use the colour tokens from `routes/layout.css` (`text-(--text-muted)`, `bg-(--primary)`, ...) so tenant branding applies. The bookings components still use raw `gray-*` classes; convert them to tokens when you touch them.
